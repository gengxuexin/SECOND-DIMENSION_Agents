# 第二部分：用 AI 改造过的业务流程说明

> 这份讲的是**业务流程本身**的改造，而不只是技术实现。
> 参照对象：我姐姐的服装店 + 网店的实际运营流程。

## 2.1 改造前的流程（纯人工）

```
【上新流程】每件衣服
  拍照 → 手动起文件名 → 手动归类（连衣裙？毛衣？外套？）
       → 手动填标签（款/色/码）→ 手动录系统（品类/款式/颜色/价格/库存）
  单件耗时：约 3-5 分钟。20 件新款 = 1-2 小时
  问题：靠记忆和手感，标签写法不统一（"外套/风衣/大衣"混用）

【评论处理】每天几十到上百条
  人工翻评论 → 找差评 → 手动归类问题（尺码? 色差? 质量? 物流?）
             → 手动抄进表格 → 手动判断哪些是共性问题
  单次耗时：约 20-30 分钟才能翻完一遍
  问题：长尾问题（10 条里 1 条的尺码问题）根本发现不了

【决策】看表格 + 凭经验
  补什么货？改什么细节？ → 靠感觉，没有数据支撑
```

## 2.2 改造后的流程（AI 辅助）

```
【上新流程】每件衣服
  拍照 → 拖进网页「图像归档」→ 自动分类 + 标签归一 + 置信度显示
       → 低置信的自动标「待人工确认」（不阻塞后续）
       → 人工只需确认那几个不确定的 → 填价格/库存 → 入库
  单件耗时：约 20-30 秒。20 件新款 = 10 分钟
  收益：约 10 倍提速，且标签写法统一

【评论处理】一键
  「看看最近评论里尺码、颜色、质量有什么问题」
  → 自动逐条打分（情感 + 多标签主题）
  → 按品类聚合出主题（带证据评论 id）
  → 冲突/低置信的主题自动转人工
  单次耗时：约 10 秒覆盖全店评论
  收益：从"每天翻一遍"变成"随时可查"，且能发现长尾问题

【决策】有据可依
  「根据评论和库存给我一些选品建议」
  → 自动关联：主题 + 库存 + 定价 → 生成建议
  → 每条建议都带：引用工具、证据评论 id、置信度
  → 例：「【毛呢半身裙】库存仅 12 件，需确认补货（置信度 0.70）
         引用工具：query_products#sku=SKU-1007, query_comments#len=12
         证据评论：C-013, C-025」
```

## 2.3 改造前后的对照

| 环节 | 改造前 | 改造后 | 变化 |
|---|---|---|---|
| 单件商品归档 | 3-5 分钟（纯人工） | 20-30 秒（AI + 确认低置信项） | **约 10 倍提速** |
| 标签一致性 | 靠记忆，同款不同叫法 | 标准标签 + 别名映射 + 低置信转人工 | **写法统一** |
| 20 件批量上新 | 1-2 小时 | 约 10 分钟 | **节省约 1 小时** |
| 评论巡检 | 20-30 分钟/次，每天一次 | 约 10 秒，随时可查 | **约 150 倍提速** |
| 长尾问题发现 | 基本发现不了 | 主题聚合 + 证据可溯源 | **从 0 到 1** |
| 补货决策 | 凭经验 | 带库存 + 定价 + 评论证据 | **有据可依** |
| 结果可追溯 | 无记录 | 全链路轨迹（每次工具调用含耗时） | **可归因** |
| 结论可信度 | 不知道模型对不对 | 自动采信率 31.6%，其余转人工 | **自知之明** |

## 2.4 改造中最关键的一环：没有"AI 全自动"

这是我要重点说明的。**如果只是追求"全自动"，这套系统反而会害店主。**

所以流程里特意设计了三道人工闸门：

```
闸门 1：标签归一置信度 < 0.65
        → 不自动采用，转人工
闸门 2：分类置信度 < 0.70 或多后端结论冲突
        → 标记待人工，不阻塞后续流程
闸门 3：建议无证据引用，或单条证据的主题
        → 不自动采信，转人工
```

**实际运行数据**：自动采信率 **31.6%**，其余 68% 进人工队列。

> 这个数字乍看很低，但它恰恰说明系统**没有假装自己很厉害**。
> 68% 转人工意味着：店主只需要确认 68% 的部分（而且低置信项往往就是模型拿不准的），
> 而不是去检查 100% 的结论。**把"检查所有结果"变成"确认可疑结果"，才是真正的提效。**

人工确认后的修正会回流到 `var/human_corrected_samples.jsonl`，作为下一轮 few-shot 与回归的输入——
**人工投入不会白费**。

## 2.5 AI 在流程里的边界（明确划清）

| 环节 | AI 做 | 人做 |
|---|---|---|
| 图片分类 | 分类 + 打分 | 低置信项确认 |
| 标签归一 | 别名匹配 | 新标签确认 |
| 评论情感/主题 | 逐条打分 + 聚合 | 冲突主题复核 |
| 库存分析 | 计算 + 关联 | 判断是否真要补货（业务决策） |
| 建议生成 | 生成带证据的草稿 | 决定采纳与否 |
| **定价** | ❌ 不做 | 完全人工（涉及市场判断和利润策略） |
| **最终决策** | ❌ 不做 | 完全人工 |

> **定价是我刻意留给人的。** 系统可以告诉你「这个品类差评集中在尺码」，
> 但「定 299 还是 329」是市场判断和利润策略，AI 越界就是添乱。

## 2.6 这套流程改造的通用性

流程本身与服装行业解耦，换个品类/行业只需替换三样东西：

```
1. 业务上下文层（store.py）—— 商品表、标签库、评论库的字段定义
2. 工具层（services/）  —— 换成该行业的确定性模型
3. 标签库（tag_library.json）—— 标准标签与别名映射
```

**编排层、状态机、治理层、评测框架、前端全部复用。**

这正是把"AI 能力"沉淀成"业务基建"而不是"一次性脚本"的意义。

---

## 2.7 一句话总结

> **改造前**：服装店的运营判断全压在店主的个人经验上，忙不过来、长尾问题看不到、决策没依据。
>
> **改造后**：把 60% 可自动化的部分（分类、打分、聚合、关联）交给 AI 并保留完整的证据链；
> 把 40% 需要业务判断的部分（低置信确认、定价、最终决策）明确留给人。
>
> **净结果不是"AI 替代了人"，而是"人从重复劳动里被解放出来，只做需要判断的事"。**
